# Ascension Report

## Neural Architecture Migration: Explicit State Management (Flax) vs. Implicit State (Keras)

When comparing Flax (built on JAX) to Keras (built on TensorFlow), the most profound architectural difference lies in state management.

### Implicit State (Keras)
In Keras, neural network layers and models are object-oriented and stateful. When you instantiate a layer (e.g., `keras.layers.Dense`), the layer object implicitly allocates and internally stores its own mutable weights and biases.
- **Forward Pass:** You perform a forward pass by simply calling the model with data (`model(x)`).
- **Updates:** The model updates its own internal state during training.
This approach intertwines the mathematical definition of the model's architecture with its physical state, which can make things like purely functional transformations or distributed execution more complex.

### Explicit State (Flax)
Flax embraces functional programming principles, making its modules entirely **stateless**. A `flax.linen.Module` is merely a declarative specification of a mathematical operation—it does not hold weights or any internal state variables.
- **Initialization (`model.init`):** Weights must be explicitly generated by calling `model.init(rng_key, dummy_input)`. This pure function returns a frozen dictionary containing all the initialized parameters.
- **Forward Pass (`model.apply`):** To compute the forward pass, you must explicitly feed the parameters back into the model alongside the input data using `model.apply(params, x)`.

### Conclusion
By completely decoupling the model architecture from its parameters, JAX/Flax enables pure functions. This statelessness makes it trivial to apply advanced JAX transformations like `jax.jit` (just-in-time compilation), `jax.vmap` (vectorization), and `jax.pmap` (parallelization) safely and efficiently, without wrestling with hidden internal states or side effects.
